# Job Tracker MVP

Локальный агрегатор вакансий из карьерных сайтов компаний и публичных API. Он хранит
историю в SQLite, обнаруживает новые, изменённые, закрытые и вновь открытые вакансии,
а также выгружает активные позиции в CSV для Excel или Google Sheets.

## Лендинг

Готовый агрегатор находится в `site/index.html`. Для обычного просмотра файл можно открыть
напрямую в браузере. Чтобы работала кнопка «Обновить вакансии», запустите `start-site.ps1`:
он откроет лендинг по адресу `http://127.0.0.1:8765/`. Кнопка запускает полный проход по
подключённым карьерным сайтам, обновляет SQLite, CSV и `site/vacancies.js`, после чего
перезагружает страницу. Повторный запуск блокируется, пока текущий проход не завершён.

Вакансии, поиск, фильтры по компаниям и технологиям и полные описания доступны на самом
лендинге; переход на сайт компании нужен только для отклика.

## Быстрый старт

1. Запустите `run.ps1`. При первом запуске он создаст `config.json` со стартовым
   списком крупных российских IT-компаний.
2. В `hh_user_agent` замените `ВАША_ПОЧТА@example.com` на настоящий контактный адрес,
   затем снова запустите `run.ps1`.
3. При необходимости отключите компании или добавьте свои.

Результаты появятся в `data/jobs.sqlite3` и `data/jobs.csv`.
Для прямых источников компаний запустите `run-direct.ps1`: он одновременно обновит базу,
CSV и лендинг. Сейчас подключены Авиасейлс, Авито, 2ГИС, Dodo Engineering, Точка,
VK, Лаборатория Касперского, Alfa Digital, Selectel, Т-Банк, Lamoda, Альфа-Банк,
ВкусВилл, Positive Technologies и X5 Tech.

`companies.top50.json` содержит реестр 50 крупнейших российских ИТ-компаний по
CNews500 2025 и состояние исследования их прямых карьерных источников.
`config.direct.json` — набор проверяемых прямых источников без hh.ru. По мере добавления
адаптеров компании переносятся из реестра в этот конфиг.

Если карьерный сайт запрещает автоматический сбор или не публикует машиночитаемый список,
компания остаётся в каталоге со ссылкой на официальный сайт, но её вакансии не попадают
в общую выдачу. Ограничения сайта не обходятся, а hh.ru не используется как автоматическая
подмена прямого источника.

Универсальные HTML-источники по умолчанию имеют `authoritative: false`: они находят
новые и изменённые вакансии, но не закрывают исчезнувшие, пока не подтверждено, что
парсер видит все страницы выдачи. Для полного API/пагинированного адаптера флаг можно
переключить в `true`.

### Как найти идентификатор источника

- hh.ru: в URL вида `https://hh.ru/employer/1740` значение `1740` является
  `employer_id`. `area: "113"` ограничивает выдачу Россией. Стартовый файл
  `config.russia.json` уже содержит Яндекс, VK, Ozon, Авито, Т-Банк, Kaspersky,
  Selectel, МТС, Сбер, SberTech и 2ГИС.
- Greenhouse: в URL вида `https://boards.greenhouse.io/COMPANY/...` значение `COMPANY`
  обычно является `token`.
- Lever: в URL вида `https://jobs.lever.co/COMPANY` значение `COMPANY` является `site`.
- Для европейского Lever используйте `"region": "eu"`.
- `max_pages` ограничивает объём одного Lever-источника (100 страниц по 100 вакансий
  по умолчанию), защищая запуск от некорректной пагинации.

Пример включённого источника Greenhouse:

```json
{
  "key": "acme-greenhouse",
  "company": "Acme",
  "type": "greenhouse",
  "token": "acme",
  "enabled": true
}
```

Для hh.ru необходимо указать собственную контактную почту в поле `hh_user_agent`.
API требует идентифицировать клиентское приложение. Почта передаётся только в заголовке
запроса; пароль, OAuth и доступ к аккаунту не нужны.

`key` должен быть постоянным и уникальным: по нему вакансии связываются между запусками.

## Команды

```powershell
# Синхронизация
python job_tracker.py --db data/jobs.sqlite3 sync --config config.json

# Только активные вакансии
python job_tracker.py --db data/jobs.sqlite3 export --output data/jobs.csv

# Активные и закрытые вакансии
python job_tracker.py --db data/jobs.sqlite3 export --all --output data/jobs-all.csv

# Обновить вакансии на лендинге из базы
python job_tracker.py --db data/jobs.sqlite3 site-data --output site/vacancies.js

# Краткая статистика
python job_tracker.py --db data/jobs.sqlite3 stats

# Тесты
python -m unittest discover -s tests -v
```

Если системный `python` недоступен, используйте путь к Python из `run.ps1`.

## Фильтры

В `config.json` можно оставить только нужные должности и локации:

```json
"filters": {
  "title_keywords": ["backend", "java", "python"],
  "locations": ["remote", "moscow"]
}
```

Пустой список означает «не фильтровать». Поиск нечувствителен к регистру и работает
как логическое И между группами: подходит одно ключевое слово должности и одна локация.

## Проверка актуальности

Вакансия становится закрытой после двух последовательных успешных синхронизаций,
в которых источник её не вернул. Порог задаётся параметром
`close_after_missing_runs`. Если запрос к источнику завершился ошибкой, вакансии этого
источника не помечаются отсутствующими.

## Регулярный запуск в Windows

### Ночное обновление, онлайн-сайт и Telegram

Для рабочего режима рекомендуется сценарий `setup-nightly-task.ps1`: он подключает
Telegram, сохраняет токен через Windows DPAPI и создаёт задачу `JobTrackerNightly`
на 03:00 каждый день. Фильтр уведомлений хранится в `config/telegram-filter.json`;
по умолчанию приходят только новые Java-вакансии.

Для круглосуточной работы без включённого домашнего компьютера проект также содержит
`.github/workflows/nightly.yml`. Он запускается в 03:15 МСК, обновляет вакансии,
отправляет уведомления и публикует свежую папку `site` на GitHub Pages. Подробная
настройка находится в `DEPLOY.md`.

В `site/vacancies.js` при каждой успешной выгрузке записывается точное время сборки.
Лендинг показывает его как «Последнее обновление» по московскому времени.

### Ежечасное обновление и Telegram

Запустите `setup-hourly-task.ps1`. Скрипт:

1. попросит токен нового бота, созданного через `@BotFather`;
2. предложит отправить боту `/start` и сам определит ID вашего чата;
3. предложит выбрать технологии для уведомлений — по умолчанию `Java`;
4. отправит тестовое сообщение;
5. зафиксирует текущую вакансию как стартовую точку, поэтому старые записи не придут;
6. зарегистрирует задачу Windows `JobTrackerHourly` с запуском каждый час.

Токен хранится в `config/telegram-bot.credential.xml` в зашифрованном Windows DPAPI
виде и доступен только текущему пользователю Windows. После каждого запуска сначала
обновляется база, затем каждая новая вакансия отправляется отдельным сообщением со
ссылкой, а после этого обновляются CSV и лендинг. При временной ошибке Telegram курсор
не сдвигается: неотправленное сообщение будет повторено в следующий час.

Фильтр находится в `config/telegram-settings.json`. Непустые группы объединяются по
правилу И, а значения внутри одной группы — по правилу ИЛИ. Например:

```json
{
  "chat_id": "123456789",
  "filter": {
    "technologies": ["Java"],
    "keywords": ["backend", "spring"],
    "companies": ["Яндекс", "Т-Банк"],
    "locations": ["Москва", "Удалённо"]
  }
}
```

Такая настройка пропустит Java-вакансии, в которых есть `backend` или `spring`, от
Яндекса или Т-Банка, с Москвой или удалённой работой. Пустая группа не ограничивает
выдачу. Доступные значения технологий совпадают с фильтром на лендинге: `Java`,
`Kotlin`, `Python`, `Go`, `JavaScript`, `TypeScript`, `C# / .NET`, `C / C++`, `PHP`,
`Ruby`, `Scala`, `Rust`, `SQL`, `Data / ML`, `DevOps / SRE`, `QA`.

Журнал фоновых запусков находится в `logs/hourly.log`. Ручной запуск того же процесса:

```powershell
.\run-hourly.ps1
```

Удалить расписание можно командой:

```powershell
Unregister-ScheduledTask -TaskName JobTrackerHourly -Confirm:$false
```

### Ручная настройка Планировщика

Создайте задачу в «Планировщике заданий»:

- программа: `powershell.exe`;
- аргументы: `-NoProfile -ExecutionPolicy Bypass -File "ПОЛНЫЙ_ПУТЬ\run.ps1"`;
- периодичность: раз в 6–24 часа.

Прямые API hh.ru, Greenhouse и Lever предпочтительнее HTML-скрейпинга: их ответы
структурированы, публичны для опубликованных вакансий и меньше ломаются при изменении
дизайна карьерной страницы.
